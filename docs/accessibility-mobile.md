# Accessibility & Mobile Readiness

## Accessibility standards for the final report

Before portfolio publication, validate each report page against this checklist:

- Meaningful page titles and section headings
- Sufficient text/background contrast
- No business meaning conveyed by color alone
- Consistent risk semantics across pages
- Keyboard-friendly tab order
- Descriptive visual titles
- Alt text for business-critical visuals
- Avoid excessively small fonts
- Tables expose clear column names and units
- Slicers have understandable labels
- Decorative visuals are not placed before critical content in tab order

## Color semantics

Use the same semantic meaning everywhere:

- Healthy / positive: success treatment
- Warning / attention: amber treatment
- Critical / stockout / severe exception: red treatment
- Neutral / contextual: gray or standard theme treatment

Avoid relying only on red/green differences for accessibility; pair color with text, labels or icons.

## Mobile layout

Create a mobile layout for the most important executive experience rather than trying to reproduce all 14 desktop pages.

Recommended mobile pages:

1. Executive Overview
2. Inventory Intelligence
3. Procurement & Supplier Performance
4. Order Fulfillment & Backorders
5. Sales & Demand Intelligence

Recommended order:

- Page title
- 3–5 critical KPI cards
- primary trend
- top exception visual
- compact slicers

## Acceptance evidence

Capture:
- one mobile-layout screenshot
- one keyboard/tab-order check
- one accessibility review note
- final Executive page at 100% zoom

The PBIR source remains the authoritative desktop report definition; mobile-specific adjustments should be saved back into the PBIP project after validation in Power BI Desktop.
